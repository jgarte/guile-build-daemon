* Guix Daemon (gxd)

A Guile implementation of a build daemon for Guix (targeting v2.0).

** Project namespace

The =gxd= is used as a namespace for the next implementation of Guix Daemon.

The rationale behind choosing =gxd= namespace is the following:
- short and makes a concise prefix
- ends on =d= as in ~sshd~, ~mpd~, etc.
- distinct and does not collide with other Guix/Linux namespaces
- 'rhymes' with the legacy C++ =nix= daemon
- sounds native :)

** Getting Started

Start the nREPL server:

#+BEGIN_SRC bash
  make ares
#+END_SRC

** Glossary

The terms =derivation=, =store=, (build) =daemon=, =client= and (client-daemon) =socket=
are the core concepts and components of Guix. Those are defined in [[https://guix.gnu.org/manual/devel/en/guix.html][GNU Guix
Reference Manual]].

The terms for the new (sub-)components introduced in the current project are
defined below.

To distinguish between the old (legacy) and the new implementation of Guix
Daemon (presumably to be included in Guix v2.0) we refer to the former as
=v1-daemon= (as in =guix-v1-daemon=) and the later as =v2-daemon= (as in
=guix-v2-daemon=).

=v1-daemon= (=nix=) - (legacy) C++ daemon ported from [[https://github.com/NixOS/nix][nix package manager]]. It can be
also referred to as =nix=. Its source code lives in the =./nix= directory of Guix
(v1) repository.

=v2-daemon= (=gxd=) - Guile implementation of Guix Daemon. Unified implementation
language makes it the native daemon. This new implementation is targeting Guix
v2.0. It can be also referred to as =gxd= (the current project's namespace).

=fallback-daemon= (assumes =fallback-v1-daemon=) - the =v1-daemon= process that is
used as a fallback for operations that are not yet implemented in =v2-daemon=.

=relay= - a process that listens on two specified sockets (e.g., =client= to
=v2-daemon= socket and =v2-daemon= to =fallback-daemon= socket) and sends RPCs from one socket to anthother both ways. It also logs parsed RPCs for inspection.

=testbox= - mount and user namespace isolated environment for testing and logging
guix client/daemon interactions. Mount namespace provides a clean filesystem for
inspecting changes in daemon's artifacts and guix state without modifying the
state of host system. The user namespace emulates daemon and client users.

=v1-testbox= - logging environment with running =v1-daemon= that communicates with
the =client= via logging =relay=

=v2-testbox= - environment with running =v2-daemon= (with logging =relay= added as
guile module =fallback-daemon= (=v1-daemon=)

=differential-test= (=diff-test=) - test suites based on comparing logs and
artifacts of =v1-testbox= and =v2-testbox= to ensure the backward compatibility of
new implementation of guix daemon (=gxd=)


** Contributing

The formating of commit messages follows simple [[https://scopedcommits.com][Scoped Commits]] standard:

#+BEGIN_EXAMPLE
  <scope>: <description>
#+END_EXAMPLE

=<scope>= - the subsystem, area, or module that the commit touches
=<description>= - a short description of the changes made
