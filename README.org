* Guix Daemon (gxd)

A Guile implementation of a build daemon for Guix (targeting v2.0).

** Project namespace

The =gxd= is used as a namespace for the next implementation of Guix Daemon.

The rationale behind choosing =gxd= namespace is the following:
- short and makes a concise prefix
- ends on =d= as in ~sshd~, ~mpd~, etc.
- distinct and does not collide with other Guix/Linux namespaces
- 'rhymes' with the legacy C++ =nix= daemon
- sounds native :)

** Getting Started

Start the nREPL server:

#+BEGIN_SRC bash
  make ares
#+END_SRC

** Differential Test

The differential test runs the same Guix client command in two separate
rootless containers, each with a seeded =/gnu/store=, and compares the results:

1. the *regular* container talks directly to a fallback =guix-daemon=;
2. the *relay* container talks to the =gxd= relay (which in turn talks to its
   own fallback =guix-daemon=).

It then compares:
- exit code
- stdout
- stderr
- filesystem delta (=gnu/store-upper=, =var/guix=, =etc/guix=), where
  =gnu/store-upper= is a writable store view seeded with links to the required
  host store items.

Using two containers removes the need for any "reset state" step between runs.

The containers run rootless via =unshare= (user + mount namespaces), so =sudo=
is not required.  Start each prerequisite in its own terminal:

#+BEGIN_SRC bash
  make container/regular/start
  make daemon-fallback/regular/start

  make container/relay/start
  make daemon-fallback/relay/start
  make daemon/relay/start
#+END_SRC

Run the test:

#+BEGIN_SRC bash
  make test/differential
#+END_SRC

Stop the containers when done:

#+BEGIN_SRC bash
  make container/regular/stop
  make container/relay/stop
#+END_SRC

Artifacts and a summary report are written to =tmp/daemon-differential/=.

*** Configuration

The test is configured through environment variables (defaults in
=env/dev/gxd/config.defaults.sh=):

General:
- =GXD_TEST_COMMAND=       (default: =guix gc --list-roots=)
- =GXD_TEST_ARTIFACTS_DIR= (default: =tmp/daemon-differential=)
- =GXD_TEST_EXPECT_EXIT=   (default: =0=)

Regular scenario (direct fallback daemon):
- =GXD_TEST_REGULAR_ROOT=          (default: =/tmp/gxd-overlayfs-regular-<user>=)
- =GXD_TEST_REGULAR_CONTAINER_PID= (optional)
- =GXD_TEST_REGULAR_SOCKET=        (default: =/tmp/gxd-fallback-regular-<user>.sock=)

Relay scenario (=gxd= → fallback daemon):
- =GXD_TEST_RELAY_ROOT=            (default: =/tmp/gxd-overlayfs-relay-<user>=)
- =GXD_TEST_RELAY_CONTAINER_PID=   (optional)
- =GXD_TEST_RELAY_SOCKET=          (default: =/var/guix/daemon-socket/socket=)
- =GXD_TEST_RELAY_SOCKET_HOST=     (default: =<relay-root>/var/guix/daemon-socket/socket=)
- =GXD_TEST_RELAY_FALLBACK_SOCKET= (default: =/tmp/gxd-fallback-relay-<user>.sock=)

** Glossary

The terms =derivation=, =store=, (build) =daemon=, =client= and (client-daemon) =socket= are the core concepts and components of Guix. Those are defined in [[https://guix.gnu.org/manual/devel/en/guix.html][GNU Guix Reference Manual]].

The terms for the new (sub-)components introduced in the current project are defined below.

To distinguish between the old (legacy) and the new implementation of Guix Daemon (presumably to be included in Guix v2.0) we refer to the former as =v1-daemon= (as in =guix-v1-daemon=) and the later as =v2-daemon= (as in =guix-v2-daemon=).

=v1-daemon= (=nix=) - (legacy) C++ daemon ported from [[https://github.com/NixOS/nix][nix package manager]]. It can be also referred to as =nix=. Its source code  lives in the =./nix= directory of Guix (v1) repository.

=v2-daemon= (=gxd=) - Guile implementation of Guix Daemon. Unified implementation language makes it the native daemon. This new implementation is targeting Guix v2.0. It can be also referred to as =gxd= (the current project's namespace).

=fallback-daemon= (assumes =fallback-v1-daemon=) - the =v1-daemon= process that is used as a fallback for operations that are not yet implemented in =v2-daemon=.

=relay= - a process that relays RPCs between two sockets (e.g., =client= to =v2-daemon= socket and  =v2-daemon= to =fallback-daemon= socket) and logs the calls and payloads. It is implemented both as guile module (e.g., to include into =v2-daemon= to relay fallback RPCs) and as stand alone (RPCs logging) package.

=sandbox= - mount and user namespace isolation environment for testing and logging guix client/daemon interactions. Mount namespace provides a clean filesystem with mounted =/gnu/store= to =/etc/guix= to a host directory for inspecting change in daemon's artifacts and guix state. The user namespace emulates =guix-daemon= user and client user (e.g., =user=). The =sandbox= provides isolation so that experiments and testing does not interfere with or break the running (GuixSD) system as well as possibility to track and record filesystem changes for testing.

=v1-sandbox= - logging environment with running =v1-daemon= that communicates with the =client= via logging =relay=

=v2-sandbox= - environment with running =v2-daemon= (with logging =relay= added as guile module =fallback-daemon= (=v1-daemon=)

=differential-test= (=diff-test=) - test suits based on comparing logs and artifacts of =v1-sandbox= and =v2-sandbox= to ensure the backward compatibility of new implementation of guix daemon (=gxd=)

** Contributing

The formating of commit messages follows simple [[https://scopedcommits.com][Scoped Commits]] standard:

#+BEGIN_EXAMPLE
  <scope>: <description>
#+END_EXAMPLE

=<scope>= - the subsystem, area, or module that the commit touches
=<description>= - a short description of the changes made
